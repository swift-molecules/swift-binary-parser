# swift-binary-parser

Use this package to decode byte input into Swift values. For a structured format (sequences, alternatives, repetition, recursion, LEB128), describe the grammar with `Binary.Machine.build(_:)` or `Binary.Machine.recursive(maxDepth:_:)`. This produces a `Binary.Machine.Parser<Output>`, which you run on a byte span with `parse`, `parsePrefix` or `parseWhole`, or wrap in `Binary.Parser<Value>` with `Binary.Parser.machine(_:)` to run it on an `ArraySlice<Byte>`. For a single fixed-layout value from an `ArraySlice<Byte>`, use `Binary.Parse.Variable<T>`, `Binary.Parse.Validated<T>`, `Binary.Parse.Converting<Source, Target>` or `Binary.Parse.Inline<Count, Element>`, and reach them through `.parse.prefix` or `.parse.whole` (`Binary.Parse.Access<P>`). To make a type decode itself from a byte collection, conform it to `Binary.Parseable`. `ASCII.Decimal.Machine` parses ASCII decimal integers as machine parsers. To convert a complete byte array to an integer without a cursor, use swift-binary's `init?(bytes:endianness:)` directly.

## Laws

- `Binary.Machine.oneOf` is ordered choice. Each alternative starts from the position where the choice began. The first alternative that succeeds commits: a later failure never backtracks into the remaining alternatives. When every alternative fails, the last alternative's fault is thrown.
- `Binary.Machine.many` and `Binary.Machine.fold` are greedy and never fail. They stop at the first element that fails, rewind to the end of the last complete element, and return the elements (or accumulator) gathered so far, which may be empty (or `initial`).
- `Binary.Machine.optional` never fails. If its child fails, even partway through, the input rewinds to where the child started and the result is `nil`.
- Every fault can be recovered by an enclosing `Binary.Machine.oneOf`, `Binary.Machine.many`, `Binary.Machine.fold` or `Binary.Machine.optional`, the same way input shortfalls are: this includes faults thrown from `tryMap` and depth faults.
- `Binary.Machine.many` and `Binary.Machine.fold` also stop at an element that succeeds without consuming input. That element is dropped (not appended, not combined), so `many` over a child that never consumes returns an empty array.
- If a fault reaches the caller, the input is not rewound. It stays where the failing step left it.
- `Binary.Machine.recursive(maxDepth:_:)` counts nested entries through its reference. Entering past `maxDepth` faults with `.depthExceeded(limit:)`. A `nil` limit means recursion is unbounded. The interpreter keeps its own frame stack, so deep nesting does not grow the Swift call stack.
- Unsigned LEB128 and signed LEB128 fault with `.insufficientBytes(need: 1, have: 0)` when the input ends before a terminating byte. They fault with `.leb128Overflow` when the encoding exceeds 64 bits.
- On byte spans, `parse` and `parsePrefix` accept trailing bytes. `parseWhole` faults with `.expectedEnd(remaining:)`, which carries the exact number of unconsumed bytes, and `Binary.Parser.parseWhole(_:)` does the same. `parsePrefixUnchecked` behaves exactly like `parsePrefix`. Span entry points copy the bytes first, so results never borrow from the span, and the consumed count is measured from the span's own start.
- `Binary.Parse.Access.whole(_:)` reports a parser failure as `.left` and leftover input as `.right(.end(remaining:))`.
- `Binary.Parseable` conformances for `RawRepresentable` and `UInt32`, and `RawRepresentable.parser`, always decode little-endian.
- `Binary.Parseable` conformances for `Swift.Array`, `ArraySlice` and `ContiguousArray` of `Byte` consume all remaining input.
- In `Binary.Parseable`, `Binary.Parse.Validated<T>`, `Binary.Parse.Converting<Source, Target>` and `RawRepresentable.parser`, a short input consumes nothing. A value that decodes but is rejected (an invalid raw value or a target overflow) has already consumed its bytes.
- `Binary.Parse.Variable<T>` reads between 1 and `MemoryLayout<T>.size` bytes, and its initializer traps for any other count. When `T` is signed, it sign-extends from the most significant byte read.
- `ASCII.Decimal.Machine` requires at least one digit and accepts any number of leading zeros. `signed` accepts an optional `+` or `-` (so `-0` is valid). `unsigned` rejects any sign with `.predicateFailed(byte:)`. A value that is too large for the type faults with `.outOfRange` after consuming every digit. It never succeeds on a shorter prefix.
